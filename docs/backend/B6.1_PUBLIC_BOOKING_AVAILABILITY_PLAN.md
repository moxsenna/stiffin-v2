## 3. Schema & Persistence: `availability_rules`

### 3.1 Table Definition
```sql
CREATE TABLE IF NOT EXISTS "availability_rules" (
  "id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "organization_id" UUID NOT NULL REFERENCES "organizations"("id") ON DELETE CASCADE,
  "day_of_week" INTEGER NOT NULL CHECK ("day_of_week" BETWEEN 0 AND 6), -- 0=Sunday, 1=Monday, ..., 6=Saturday
  "start_time" TEXT NOT NULL CHECK ("start_time" ~ '^([01][0-9]|2[0-3]):[0-5][0-9]$'), -- HH:mm (24h)
  "end_time" TEXT NOT NULL CHECK ("end_time" ~ '^([01][0-9]|2[0-3]):[0-5][0-9]$'),   -- HH:mm (24h)
  "is_active" BOOLEAN NOT NULL DEFAULT true,
  "created_at" TIMESTAMPTZ NOT NULL DEFAULT now(),
  "updated_at" TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT "availability_rules_time_order_check" CHECK ("start_time" < "end_time")
);

CREATE INDEX IF NOT EXISTS "idx_availability_rules_org_day"
  ON "availability_rules" ("organization_id", "day_of_week")
  WHERE "is_active" = true;
```

### 3.2 Runtime Grants Arithmetic
- `availability_rules` will receive standard CRUD grants: `SELECT, INSERT, UPDATE, DELETE`.
- Capability update: +4 capabilities $\rightarrow$ Total runtime capability checks = $94 + 4 = \mathbf{98}$.

## 4. Slot Generation Engine (Pure Domain Architecture)

Located in `apps/platform-api/src/domain/flow/slots.ts` (100% pure TypeScript, no DB / no IO dependencies).

### 4.1 Inputs & Calculation Protocol
```ts
export interface GenerateSlotsInput {
  organizationTimezone: string; // e.g. "Asia/Jakarta"
  rangeFrom: Date;              // Query start UTC
  rangeTo: Date;                // Query end UTC
  durationMinutes: number;      // Selected service duration
  weeklyRules: AvailabilityRule[];
  existingBookings: { startAt: Date; endAt: Date; status: string }[];
}

export interface AvailableSlot {
  startAt: string; // ISO 8601 UTC
  endAt: string;   // ISO 8601 UTC
  localDisplay: string; // "10:00 - 11:00 WIB"
}
```

### 4.2 Exclusion Rules
A candidate slot $[S_c, E_c)$ is excluded if:
1. It falls outside active `availability_rules` for the local weekday in the organization timezone.
2. It overlaps with any existing booking with status `PENDING`, `CONFIRMED`, or `COMPLETED`.
3. It falls in the past relative to the current evaluation timestamp (`now + bufferMinutes`).

## 5. API Endpoint Specifications

### 5.1 Public Endpoints (Anonymous / Rate-Limited)
- **`GET /api/v1/public/:slug/slots`**:
  - Query parameters: `serviceId` (UUID), `from` (ISO date), `to` (ISO date).
  - Rate limiting: 60 requests/minute per client IP.
  - Response: `{ slots: AvailableSlot[], service: { id, name, durationMinutes, priceAmount } }`.

- **`POST /api/v1/public/:slug/bookings`**:
  - Request body:
    ```json
    {
      "serviceId": "uuid",
      "startAt": "2026-08-20T10:00:00Z",
      "name": "Budi Santoso",
      "phoneRaw": "+6281299990001",
      "email": "budi@example.com",
      "notes": "Konsultasi minat bakat anak",
      "locationType": "ONLINE"
    }
    ```
  - Behavior:
    - Atomically finds or creates Shared Core `contacts` record.
    - Ensures Flow contact profile exists with `interest` from service name / notes.
    - Verifies slot is still available using `SELECT ... FOR UPDATE` booking concurrency lock.
    - Creates `bookings` record with `status: 'PENDING'`, `payment_status: 'UNPAID'`, and server price snapshot.
    - Creates `next_actions` record (`CONTACT_LEAD` or `CONFIRM_BOOKING`).
    - Appends `BOOKING_CREATED` activity.
  - Response (201 Created): `{ bookingId: "uuid", status: "PENDING", amount: 350000 }`.

### 5.2 Operator Availability Settings Endpoints (Authenticated)
- **`GET /api/v1/flow/availability`**: Lists weekly availability rules.
- **`PUT /api/v1/flow/availability`**: Replaces weekly rules in a single transaction.
